使用者已指定：Android V1.0 基礎功能及 UI 真機通過以前，延後 iOS 真機，保持 CI／靜態相容。
這是排程順序，不刪除 P0 的 iPhone 交接條件。V1.0 另有路線、計時、歷史等範圍，
本文件不宣稱完成其產品驗收，也不藉由重新命名里程碑提前解除 iOS 延後決定。
第二品牌 Android 為 master plan 的覆蓋要求，單一機型不能取得通用 Android 支援結論。

## 3. 證據與判定規則

- 結果限 `pass / fail / blocked / untested / not_applicable`；blocked 或 untested 不算通過。
- 使用 `automated tests / mock tests / static validation / manual tests / hardware tests` 標示證據。
- 每案保存前置條件、版本、預期、實際、可重現步驟、失敗原因與完整輸出。
- 真機原始檔、個別統計、測試 manifest、參考錄影及報告只放本機 Git 忽略的私有目錄。
  Git／PR 只放流程、合成案例及不含個別統計的門檻狀態；不複製既有私人資料。
- 沿用 `05-mac-iphone-checklist.md` 報告欄位，另加 APK／契約版本、缺樣原因與保存策略。
  報告私有保存；由使用者在 PR #2 宣告交接，不要求上傳統計以滿足報告條件。
- 定位 availability、感測器 availability、資料格式正確與量測精度分別判定。
  無新樣本但序號連續，不等於沒有採集中斷；驗證器零樣本通過不等於採集成功。
- 警告逐項列出預期與原因，不要求抹除合法向前相容警告；本版新增且可解決的
  UNKNOWN_QUALITY_FLAG 必須完成契約對齊，不能永久當作無害例外。
- 舊版證據保留為 regression baseline；未取得新版證據的格子保持 untested。

## 4. P0 與整合版案例

以下為待執行矩陣，不把歷史測試填為本版 pass。除另註外，先以合成／失敗注入
驗證確定性行為，再執行真機；缺少任一必要證據須明列。

| ID | 場景 | 通過條件 | 證據／歸屬 |
|---|---|---|---|
| P01 | 無登入／無網路開始、停止、匯出 | 可記錄本機資料；停止完成後檔案不再追加；App 匯出完整可讀 | manual + hardware；Codex |
| P02 | 權限請求、拒絕通知、定位降級／撤銷、關閉定位 | 說明真實狀態；不把舊速度當即時、不以 0 冒充無效值；合法恢復路徑可用 | mock + hardware；Codex |
| P03 | 鎖屏、切 App、滑掉近期清單、重開 UI | 先取得非零 GPS 樣本；持續寫入或明確記錄中斷，UI 與原生一致；連續採集案例若中斷即 fail | hardware；Codex |
| P04 | 非零序號後程序死亡並續錄 | 同 recordingId，已存序號無重複／逆序，恢復事件合理；缺口不補造；UI 區分 resuming／interrupted／recording | automated + hardware；Codex |
| P05 | 中斷後選擇結束、force-stop 後重開 | 結束後可匯出；不假裝已持續記錄；強制停止不承諾背景自動重啟 | automated + hardware；Codex |
| P06 | 跨開機手動續錄 | 無自動開機錄製；保留 recordingId／序號，boot 時間域切開，reason 正確；校準失效、新段最大值 null | automated + hardware；Codex；跨層語義由契約確認 |
| P07 | GPS 不可用後恢復 | 保存真實空窗與品質；舊速度過期；恢復後新樣本時間／序號正確；不宣稱地下環境仍有 GPS | hardware；Codex；計時跨缺口規則由 timing_core 擁有者驗證 |
| P08 | Android 30 分鐘及 2 小時，各一筆 | 分別前景 5／鎖屏 20／前景 5 分、前景 10／鎖屏 100／前景 10 分；不充電；正常停止／匯出；格式無 error；無無法解釋的資料遺失 | hardware；Codex |
| P09 | iPhone 30 分鐘及 2 小時，各一筆 | 同等鎖屏／不充電證據；睡眠單調時鐘、權限、暫停與恢復正確；當時版本契約通過 | hardware；延後，不能以 CI 代替 |
| P10 | UI 全主流程 | 開始、等待定位、過期、受限傾角、中斷、續錄、結束、匯出均可操作；重開不重複啟動 writer；停止錯誤不顯示成功 | mock + manual + hardware；Codex |
| P11 | 匯入與重讀 | 單檔重複為錯誤，完整重讀冪等；舊格式保留且不混寫；截斷尾端可處理 | automated；P0 過渡責任及後續 mobile_data 接手依共同規則 |
| P12 | 交接與 CI | 最終整合提交 checks 通過；資料核心 CI 已承接，再移除 mobile CI 的 mobile_data 責任；無未解阻擋 review；使用者宣告 | static + review；雙方依擁有權 |

P08/P09 的無遮蔽定位區段需事先標記，所有 >5 秒 GPS 缺口逐一對照
來源狀態／環境／程序事件。未知原因缺口保持 fail 或 blocked，不事後刪掉區段。
環境造成的定位不可用可通過 P07 降級案例，但不能拿來證明連續定位品質。
長測若被安裝、USB 充電或人為終止打斷，不能以累加短測時長取代。
耗電保存起迄、充電／螢幕／其他 App 條件及溫度；本階段不創造未量測的續航承諾。

## 5. 感測、容量與耐久性案例

| ID | 場景 | 通過條件 |
|---|---|---|
| D01 | 回呼 25／50／100／200 Hz、抖動、批次與速率切換 | 不依機型硬編碼除數維持目標；輸出不快於有效輸入，不補造；回呼、估算、保存、UI 各自可量測；降頻宣告符合契約 |
| D02 | 降採樣與重播 | 合成高頻震動驗證抗混疊選擇；估算使用的完整必要輸入／狀態可追溯；相同保存輸入與版本可依宣告重播；stride>1 依現契約保持 replayable=false，變更先協作 |
| D03 | 品質／時鐘轉換 | 保留平台原值；演算法信心不冒充平台 accuracy；缺樣、時鐘失效、品質改變切 epoch；資料恢復後不沿用失效校準 |
| D04 | 儲存速度不足、佇列溢位、短寫、磁碟滿 | 緩衝有界，事件不無限堆積；序號成功追加後才前進；真正丟樣可追查；保存失敗不顯示錄製正常；GPS 與 motion 故障隔離策略由第 2 階段定案 |
| D05 | raw／lean 不同寫入與 flush 邊界程序終止 | 成功保存的原始前綴可恢復；未解析引用被辨識／隔離，不直接當有效；完整前綴不改寫；重開不重複寫入 |
| D06 | 2 GiB 合成檔及損壞尾行逐檔／配對驗證 | 正式驗證器完整執行、不整檔讀入、不因引用表隨行數增長而爆記憶體；合法／非法結果與小檔語義一致；完整保留跨檔檢查 |
| D07 | 大檔匯出／重開／恢復 | 不阻塞 UI 到無法停止，不複製多份完整內容進記憶體；取消／容量不足有明確結果；既有檔案保留 |

D01～D07 先使用合成資料與受控失敗注入，真機補程序死亡、背景、停止匯出與容量行為。
SIGKILL 不等於斷電；沒有實際掉電證據時，報告只宣稱已驗證的耐久範圍。

第 2 階段設計以以下 **R1 工程目標**評估可行性，不是實測值或產品承諾：

- 三來源約 50 Hz 的目標配置下，所有紀錄檔合計不超過 300 MB／小時（十進位 MB）。
  須包含 lean、事件與診斷；不可只減少 raw 便宣稱通過。其他配置另列預算。
- 桌面正式驗證器在 2 GiB 合成檔的峰值 RSS 目標不超過 256 MiB；同時記錄耗時與暫存磁碟。
  需針對配對引用／最壞錯誤數控制記憶體，不以只驗單行 schema 達標。
- App 的緩衝容量、磁碟保留量、flush／可容忍遺失窗口與停止延遲由第 2 階段設計
  給出數值並鎖定後，才開始第 3 階段實作；沿用共同計畫正常緩衝最多約一秒的設計目標，
  不把它等同硬斷電遺失保證。

## 6. 傾角分級驗收

受限實驗模式允許觀察未驗證角度；自動參考停用、正式最大值 null、
extremumEligible=false、品質旗標及 UI 提示一致。這條降級路徑可以通過功能驗收，
但不得勾選下列正式準確度案例。品質可信模式的自動參考也需另有真機證據。

| ID | 場景 | 判定 |
|---|---|---|
| L01 | 無校準、軸未知、品質不足、校準失效 | 不產生正式角度／最大值；受限顯示明示實驗；恢復來源後仍尊重校準有效性 |
| L02 | 安裝與左右校準 | 固定於車身的相對姿態已知；左右符號正確；重新安裝／支架位移需重校準；車把轉向誤差單獨記錄 |
| L03 | 參考靜態角度與回零 | 已知角度 0、左右 10／20 度，支架允許時再加 30 度；每姿勢穩定窗口 10 秒、往返三次；穩定窗口絕對誤差 P95 ≤3 度、各次回零中位誤差 ≤2 度 |
| L04 | 固定姿勢、引擎震動與溫度變化 | 固定姿勢十分鐘，末／首各 30 秒誤差中位差 ≤2 度，整段誤差 P95 ≤3 度；有效輸出覆蓋率 ≥95%，不可用一直 null 取得防漂移通過 |
| L05 | 道路動態參考比較 | 已定義情境內絕對誤差 P95 ≤5 度、獨立量測延遲 ≤200 ms、有效輸出覆蓋率 ≥95%；不同速度／轉向／加減速情境分開報告，不用總平均掩蓋失敗 |
| L06 | 自動直立參考與正式最大值 | 只在合格輸入建立；軸未知維持 null；手動優先；新分段不承襲最大值；不合格估算不可進入 extrema |

L03～L05 的數字是尚未證實可達成的 **R1 工程驗收目標**，不是現有精度宣稱。
靜態參考不確定性應 ≤0.5 度；動態參考目標 ≤1 度、時序對齊不確定性 ≤20 ms，
須獨立於手機平台融合結果。達不到參考條件就 blocked，不用兩個未知精度的 App 互證。
角度誤差在事先固定的時鐘對齊上計算，不事後搜尋最佳平移以隱藏延遲。
覆蓋率分母是預先指定的整段評估時間，失效或大誤差區段不可事後移除。
只有先確認安全且具備固定治具才能做停車角度測試；不要求騎乘者操作或觀察手機，
道路案例需另定安全場地與參考設備方案，不能由這張表直接啟動。

若目標不可行，先提出證據、硬體／支架／模型限制與修訂理由，建立 R2 後再開新測試。
不可在同一輪結果出來後改門檻並把原失敗改判通過。

## 7. 下一階段的設計交付與擁有權

第 2 階段需完成一份可實作的設計與共用契約協作結果：

Codex 設計提案見 [採集與傾角可靠性設計 D1](RECORDING_RELIABILITY_DESIGN.md)，
其中明列共同契約待確認項；文件存在不等於第 2 階段已共同定案。

1. 品質：兩個實驗旗標的語義／extrema 阻擋、原始 accuracy 與演算法信心分開。
2. 頻率：時間選樣或濾波方案、四種頻率、策略切換事件／版本、aliasing 與 replayable 定義。
3. 保存：有界緩衝、寫入／flush 次序、跨檔恢復、磁碟不足／GPS 隔離、量化資源與停止預算。
4. 驗證：逐行處理、配對引用索引、有限診斷累積及 2 GiB 合成容量案例。
5. 校準／融合：偏差與震動處理、可信度降級、參考設備與安全驗證方案；若有不可觀測限制，明列支援條件。

Codex 負責 device_bridge／App／mobile CI 與手機端可實作性；contracts、其 fixtures／工具
由 Claude Code 主筆，mobile_data／timing_core 依共同規則交接邊界。
需要對方修改時先提供使用者可複製的完整協作 prompt，取得路徑擁有者同意，
不直接修改、不自動發訊息，不建立第二份共同格式。
